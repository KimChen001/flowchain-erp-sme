# Zero-data truthfulness contract v1

An empty PostgreSQL workspace is a valid state, not an API outage and not a numeric business conclusion.

Master Data reads return HTTP 200 and empty arrays. The client preserves HTTP status and distinguishes `loading`, `ready_with_data`, `ready_empty`, `unauthenticated`, `forbidden`, `not_found`, `server_error`, and `network_error`. It never substitutes frontend fixtures.

AI evidence uses five types: `business_fact`, `database_aggregate`, `navigation_context`, `policy_boundary`, and `data_limitation`. Only the first two contribute to `realEvidenceCount`. Navigation and policy cards are reported separately through `contextCardCount`; limitations use `limitationCount`.

With no authoritative records, `realEvidenceCount` is zero, confidence is low, no business-object links or review drafts are produced, and the response says that no verifiable Supplier, SKU, PO, or related business records exist.

Reports distinguish no records from numeric zero, incomplete data, and unconverted multi-currency values. Ranking controls exist only when rankings exist, and Top N values are 5, 10, or 20.
