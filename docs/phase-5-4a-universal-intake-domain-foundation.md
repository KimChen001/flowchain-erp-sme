# Phase 5.4A Universal Intake Domain Foundation

## Problem statement

External files, future email attachments, API payloads, and system exports need
one governed boundary before FlowChain can parse, normalize, review, or commit
their contents. Phase 5.4A introduces that boundary without treating uploaded
content as business truth.

```text
External source
  -> InboundArtifact
  -> IntakeBatch
  -> IntakeRecord
  -> normalization and validation
  -> ReviewSession
  -> future governed commit adapter
```

## Product boundary

Only `manual_upload` is enabled in Phase 5.4A. `email_attachment`, `api`, and
`system_export` are reserved domain values with no connected provider. CSV and
XLSX parsing, PDF/OCR, email connectors, AI mapping, and business-object commit
adapters are not implemented.

The `universal-intake` capability is preview-only and requires explicit
environment enablement. Intake data never writes Supplier, Item, Customer,
PurchaseOrder, Inventory, Invoice, or other operational tables.

Universal Intake is the sole forward-looking intake authority. The legacy
Pilot Import production service graph and direct business-table write routes
are retired. Authenticated requests to `/api/imports*` and
`/api/import-batches*` fail closed with HTTP 501 and
`FLOWCHAIN_LEGACY_IMPORT_PIPELINE_RETIRED`; unauthenticated requests remain
HTTP 401. The legacy `ImportBatch` and `ImportIssue` models remain only to
preserve historical compatibility records. They are non-authoritative and no
production route creates or mutates them.

## Domain model

- `InboundArtifact`: immutable source metadata and a generated storage
  reference; binary content remains outside PostgreSQL.
- `IntakeBatch`: tenant-scoped processing aggregate with an enforced state
  machine and optimistic `version`.
- `IntakeRecord`: bounded parsed row payload and optional normalized preview.
- `MappingProfile` and `FieldMapping`: versioned, allowlisted declarative
  transforms only.
- `ValidationIssue`: stable code, localized message boundary, severity, and
  audited resolution.
- `ReviewSession`: open, approve, reject, or cancel review decisions.
- `CommitAttempt`: durable evidence that commit was requested and blocked.
- `SourceReference`: sanitized external provenance metadata.

Every model is tenant-scoped. Parent-child relations use composite tenant keys
where Prisma supports them; services additionally reject cross-tenant IDs.

## State machine

Implemented batch states:

```text
uploaded -> profiling
profiling -> mapping_required | validation_required | failed | cancelled
mapping_required -> validation_required | failed | cancelled
validation_required -> ready_for_review | mapping_required | failed | cancelled
ready_for_review -> cancelled
```

`normalizing`, `approved`, `committing`, and `completed` are reserved contract
states. Phase 5.4A does not transition batches into them. `failed` and
`cancelled` are terminal. Status is not exposed as a generic update field.

## Database schema

Phase 5.4A adds nine explicit Prisma models rather than storing the aggregate in
`RuntimeRecord`. PostgreSQL stores metadata and bounded structured row payloads
only. Binary artifacts remain in artifact storage.

The migration is additive from the Phase 5.3.2 release schema. Rollback is a
destructive operator action: stop Intake traffic, preserve artifact storage and
export Intake audit evidence, then drop child tables before parent tables. No
automatic down migration is shipped.

## Storage boundary

`ArtifactStorage` defines `put`, `head`, `getMetadata`, and `delete`. The local
filesystem adapter is restricted to tests and explicitly configured local
development. Storage keys are generated by FlowChain and API DTOs never expose
the key or filesystem path. A future S3 adapter can implement the same port.

## Authorization

Permissions:

- `intake.artifact.create`
- `intake.artifact.read`
- `intake.batch.create`
- `intake.batch.read`
- `intake.batch.cancel`
- `intake.mapping.manage`
- `intake.review`
- `intake.commit`

The default `Intake Uploader` role can register/read artifacts and create/read/
cancel batches, but cannot manage mappings, review, or commit. The default
`Intake Reviewer` role can read artifacts/batches and manage mappings/reviews,
but cannot upload or commit. Workspace administrators receive the full catalog,
including `intake.commit`; the commit adapter still fails closed.

## Audit

The domain writes compact `AuditLog` entries for artifact registration, batch
creation and transitions, mapping lifecycle, issue resolution, review
decisions, and blocked commit attempts. Entries identify tenant, actor, action,
resource, request, before/after summary, and timestamp without file bodies,
record payloads, credentials, tokens, or storage paths.

## Payload safety

The shared policy limits artifact bytes, batch records, row bytes, fields, and
nesting depth. It accepts JSON primitives, arrays, and plain objects only;
rejects prototype keys and exact secret-field classifications; and deliberately
allows normal business names such as `supplierTokenNumber`.

## API contract

Authenticated, permission-controlled, tenant-scoped APIs expose artifact,
batch, mapping, issue, and review foundations. Responses are allowlisted DTOs,
not raw Prisma objects. Pagination uses bounded `limit` and opaque cursor IDs.

`POST /api/intake/batches/:id/commit` always persists a blocked attempt and
returns HTTP 501 with:

```json
{
  "code": "FLOWCHAIN_INTAKE_COMMIT_NOT_IMPLEMENTED",
  "message": "Governed business commit adapters are not implemented in Phase 5.4A."
}
```

## Failure model

Stable failures cover missing tenant context, authentication and permission
denial, invalid transitions, cross-tenant references, duplicates, unsafe or
oversized payloads, unsupported MIME types, optimistic-version conflicts, and
the unimplemented commit adapter. Internal storage paths, database errors, and
stacks are never returned.

## Non-goals

No full CSV/XLSX parser, PDF extraction, OCR, Outlook/Gmail/Teams/Slack
connector, AI mapping, automatic commit, business-object import adapter, S3
deployment, onboarding wizard, MRP, Forecast, or S&OP is part of Phase 5.4A.

## Known limitations

- Only manual upload is enabled.
- The local storage adapter is for tests and explicit local development.
- Normalized payloads remain previews.
- Commit attempts are always blocked.
- Historical legacy import records remain readable only through database
  administration or migration tooling; the retired production API does not
  expose or mutate them.

## Phase 5.4B readiness

Phase 5.4B starts bounded CSV/XLSX parsing only after the schema, state machine,
authorization, audit, storage, payload safety, and fail-closed commit contracts
pass their release gates. Governed business-object commit adapters remain
excluded from 5.4B and begin in Phase 5.4C.
