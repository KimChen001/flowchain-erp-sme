## Scope classification

### A. Authoritative PostgreSQL runtime

- Production repository registration accepts PostgreSQL only and rejects the
  retired JSON persistence mode.
- Procurement, purchase order, receiving, inventory, master-data, sales,
  evidence, intake, workflow, and bounded AI reads use tenant-scoped database
  authorities.
- Empty database results remain truthful empty states. Production routes do not
  import test business fixtures.
- Unsupported planning, recommendation, market, and legacy-import capabilities
  fail closed instead of returning static business facts.

### B. Local development workflow

- Local development has guarded PostgreSQL startup, migration, and explicit
  scenario-loading commands.
- Local scenario facts are loaded only by an explicit user action.
- Normal production startup never backfills missing business facts from a
  bundled JSON file.

### C. Core product recovery

- Canonical purchase-order list/detail behavior is restored with PostgreSQL
  PO, GRN, invoice, and three-way-match evidence.
- AI PO suggestions navigate to canonical business pages and focus relevant
  evidence instead of creating meaningless reviewed records.
- Sales read surfaces remain truthful when outbound writes are disabled.
- Inventory balance, warning, and empty operational views reflect the current
  database rather than invented facts.

### D. Repository governance

- The production composition root moved from the misleading
  `server/routes/scm-legacy.routes.mjs` path to
  `server/bootstrap/scm-server.mjs`.
- JSON persistence is rejected by the production adapter registry.
- Test fixtures remain under `server/domain/test-fixtures/` and outside the
  production entry graph.
- Thirty-one confirmed empty source stubs/barrels were removed.
- Current product boundaries and the remaining oversized modules are recorded
  in `docs/repository-governance-audit-2026-07.md`.

### E. Dependency cleanup

- The package identity is now `@flowchain/erp-sme`.
- Twelve zero-usage prototype dependencies were removed.
- `package-lock.json` was regenerated by the dependency removal.
- Typecheck, production build, unit/contract tests, database/API verification,
  and browser CI passed after the cleanup.

### F. Composition and route dispatcher cleanup

- Ordered API route dispatch is isolated in
  `server/bootstrap/route-dispatcher.mjs`.
- The bootstrap retains authentication, mutation guards, route-context
  construction, top-level API error handling, and static-asset fallback.
- The dispatcher extraction preserves the existing handler order and does not
  introduce automatic discovery, a plugin system, or new business behavior.

### G. Documentation and acceptance evidence

- Backend authority and repository-governance documents describe the current
  runtime rather than the retired JSON prototype.
- Product-recovery browser acceptance includes PO list/detail, AI-to-PO focus,
  sales read-only behavior, inventory facts, and procurement-workbench
  evidence.
- PR #14 remains Draft for final human acceptance.
